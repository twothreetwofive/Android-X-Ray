### 판단이 들어간 부분 3가지

**① 권한을 알파벳이 아니라 위험도 순으로 정렬**

- 등급(높음>중간>낮음) → 가중치 → 이름 순
- 권한이 12개만 돼도 접근성 권한이 `INTERNET` 아래로 밀려 안 보이기 때문

**② 값이 없을 때 0으로 채우지 않음**

- 점수 계산 실패 시 `"계산 실패"`, `min_sdk`/`target_sdk`가 `0`이면 `"파싱 실패"`로 표시
- `0`으로 적으면 **"위험도 0 = 안전한 앱"**으로 정반대로 읽힘
- 6주차에 A에게 같은 이유로 주의를 요청했던 부분을 화면에서 지킨 것

**③ 검출되지 않은 항목도 목록에서 제외하지 않음**

- "SMS 권한이 없다"는 것 자체가 정보
- 항목이 앱마다 나타났다 사라지면 여러 앱 비교 시 혼란

### 색 — 새로 정하지 않음

- 7주차 계획에 "D의 위험도 게이지와 B의 권한 강조 색을 통일" 항목 있었음
- 여기서 hex를 새로 정하면 A의 배지와 톤이 어긋남
- 따라서 **A의 `common.STATUS_COLORS`와 같은 streamlit 색 이름을 그대로 재사용**

```python
RISK_COLORS = {"high": "red", "medium": "orange", "low": "gray"}
#               = STATUS_COLORS["failed"] / ["partial"] / (초록은 미사용)
```

- 초록은 미사용 — "낮음"은 **위험 요소를 못 찾았다**는 뜻이지 안전 보증이 아닌데, 초록으로 칠하면 보증한 것으로 읽힘
- D가 게이지 제작 시 `views/static_data.RISK_COLORS`를 그대로 import하면 두 화면의 빨강이 일치

## 4. 작업 중 발견한 문제 5건

### (1) 내가 만든 샘플 데이터의 점수가 틀렸음

- 샘플에 `raw`를 손으로 `82`라고 기입
- **실제로 D의 `calculate_risk_with_breakdown()`에 넣어 보니 `140`**
- 직접 만들어 둔 "근거 합계와 raw가 맞는지" 검사(`breakdown_matches_raw`)에 걸려 발견
- 방치했을 경우 **틀린 값을 보고 화면을 맞추게 되고**, 발표 자료 캡처에도 그대로 실렸을 것
- 대응: **샘플의 점수가 실제 계산과 일치하는지를 테스트로 고정**(`test_샘플의_점수가_실제_scorer_출력과_일치한다`)
- 이유: 샘플이 거짓말을 하면 그것을 보고 맞춘 화면도 같이 틀림

### (2) [8주차 이월] `NORMALIZATION_CAP`이 낮아 점수가 100점에서 잘림

- (1)을 수정하는 과정에서 파생된 발견

| 샘플 | raw | total |
|---|---|---|
| 악성 앱 예시 | 140 | **1.0 (=100점, 잘림)** |
| 정상 앱 예시 | 12 | 0.12 |

- `NORMALIZATION_CAP`이 100인데 흔한 뱅킹 트로이목마 구성만으로 raw가 이미 140
- 즉 **"꽤 위험"과 "매우 위험"이 똑같이 100점**으로 표시됨
- D가 6주차에 "재조정 필요"라고 한 항목의 **구체적 숫자 근거**
- 조정하려면 실제 악성 샘플의 점수 분포가 필요 → 8주차로 이월

### (3) `views/`가 `app.py`의 import 순서에 의존하고 있었음

- `views/static_data.py`가 `static_analyzer`를 import하는데, `src/`를 경로에 넣어주는 것은 `pipeline_bridge.py`
- `app.py`가 우연히 `import pipeline_bridge`를 먼저 하고 있어 **동작하는 것처럼 보였음**
- `streamlit run demo_static.py`로 정적 탭만 따로 띄우자 `ModuleNotFoundError: No module named 'static_analyzer'` 발생
- 대응: `static_data.py`가 스스로 `src/`를 경로에 추가하도록 수정
- → **A에게 확인 요청 (6-A1)**

### (4) `requirements.txt`에 `streamlit` 누락

- 7주차 계획상 A가 PR에 포함하기로 돼 있었으나 골격 PR에서 빠짐
- 새로 받은 사람은 `streamlit run app.py`부터 막힘
- 대응: `streamlit==1.61.1` 추가

### (5) 가중치는 있는데 설명이 없는 권한 8개

- D가 6주차에 `PERMISSION_WEIGHTS`를 20개로 확장
- 그중 8개는 `ABUSE_EXAMPLES`에 설명이 없어 **권한 표의 "악용 예시" 칸이 공백**으로 표시
- 대상: `BIND_DEVICE_ADMIN`, `ACCESS_BACKGROUND_LOCATION`, `PACKAGE_USAGE_STATS`, `READ_CALL_LOG`, `CALL_PHONE`, `WRITE_CONTACTS`, `ACCESS_COARSE_LOCATION`, `GET_ACCOUNTS`
- `ABUSE_EXAMPLES`는 점수 계산에 미사용인 B 담당 표라 **D의 점수에 영향 없음** (6주차 확인 사항)
- 테스트로도 확인 (`test_권한_설명이_비어있지_않다`)
